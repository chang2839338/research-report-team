# Research Report Team

Local web app for running a quality-first report workflow through Codex.

The project does not call the OpenAI API directly. Semantic roles run through
`codex exec`; publication is a deterministic server step.

`Manager -> Researcher -> Evidence Auditor -> Analyst -> Writer -> Reviewer -> Revision Writer when needed -> Final Verifier -> Publisher/system`

## Run

```powershell
python .\scripts\research_team_server.py --port 8765
```

Open `http://127.0.0.1:8765` in a browser.

For higher quality research, pass the Codex model through the existing CLI option:

```powershell
python .\scripts\research_team_server.py --port 8765 --codex-model gpt-5
```

If `--codex-model` is omitted, Codex uses its configured default model.

## Quality-First Artifacts

New runs use one shared artifact contract across the server, CLI, and UI.

- `artifacts/00_task_contract.json`: structured intake and clarification gate.
- `artifacts/00_task_brief.md`: human-readable task brief.
- `artifacts/01_research.md`: research memo.
- `artifacts/01_sources.md`: source ledger.
- `artifacts/01_claims.md`: preliminary claim evidence table.
- `artifacts/01_gaps.md`: research gaps and risks.
- `artifacts/01_numeric_assumptions.md`: numeric assumptions ledger.
- `artifacts/01_source_provenance.md`: source access and query provenance.
- `artifacts/02_evidence_gate.json`: machine-readable evidence decision.
- `artifacts/02_evidence_audit.md`: human-readable evidence audit.
- `artifacts/03a_decision_frame.md`: decision frame.
- `artifacts/03b_option_evaluation.md`: option evaluation.
- `artifacts/03c_scenarios_and_recommendation.md`: scenarios and recommendation.
- `artifacts/03_analysis.md`: Writer-facing analysis rollup.
- `artifacts/03_analysis_status.json`: analysis readiness gate.
- `artifacts/04_draft.md`: Writer draft.
- `artifacts/04_writer_trace.md`: claim-to-evidence trace map.
- `artifacts/05_review_decision.json`: review decision and required revision IDs.
- `artifacts/05_review.md`: human-readable review.
- `artifacts/05_claim_audit.md`: detailed draft claim audit.
- `artifacts/06_revision.md`: revised draft when review requires it.
- `artifacts/06_revision_trace.md`: required revision coverage.
- `artifacts/07_final_verification.json`: final publication gate.
- `artifacts/07_final_verification.md`: human-readable final verification.
- `artifacts/08_final.md`: deterministic copy of the verified candidate.
- `artifacts/08_final.docx`: local Word copy generated by the server.
- `artifacts/08_final_manifest.json`: publication metadata, hashes, and final gate.

Multi-artifact Codex roles return one Markdown response with exact artifact
markers. The server validates marker presence/order and JSON sidecars. If marker
parsing fails, the server asks Codex for one repair attempt before failing.

## Workflow Notes

1. Enter a report title and brief.
2. Click the run button.
3. The server runs Codex role by role without direct API calls.
4. Publisher is shown as a workflow step but does not call Codex.
5. Prompts are saved in `prompts/`.
6. Agent replies are saved in `artifacts/`.
7. Token usage and role history are saved in `status.json`.
8. Final state is `completed` only when Markdown, DOCX, and final manifest exist.

Existing historical runs are preserved as-is; new runs use this quality-first contract.
